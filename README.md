# Лабораторна робота №3

**Дисципліна:** Технології розроблення серверних компонентів

**Тема:** Інтеграція PostgreSQL, ORM, міграцій, валідації та варіанти бізнес-логіки.

## Опис роботи

У цій лабораторній роботі було доопрацьовано REST API для обліку витрат із попередньої лабораторної.

Замість зберігання даних у пам'яті використовується PostgreSQL. Для роботи з базою даних підключено SQLAlchemy, а для керування змінами структури БД — Alembic.

Проєкт реалізовано на Python із використанням FastAPI. База даних запускається через Docker Compose, а запити тестуються у Bruno.

## Індивідуальне завдання

Номер залікової книжки — 4606.

Розрахунок варіанта:

`V = (4606 % 3) + 1 = 2`

**Варіант 2 — Персональні та глобальні категорії.**

Реалізовано 2 типи категорій:

- Глобальні (`user_id = NULL`) — доступні всім користувачам.
- Персональні (`user_id`) — належать конкретному користувачу.

Користувач може переглядати та використовувати глобальні й власні персональні категорії. При спробі використати чужу персональну категорію сервер повертає помилку `403`.

## Запуск проєкту

Для запуску потрібні Python 3 та Docker Desktop.

Спочатку запускаємо базу даних:

```bash
docker compose up -d
```

Створюємо віртуальне середовище та встановлюємо залежності:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Запускаємо сервер:

```bash
uvicorn main:app --reload
```

Після запуску документація API доступна за адресою:

http://127.0.0.1:8000/docs

Міграції Alembic застосовуються автоматично під час запуску застосунку.

## Перевірка бази даних

Переглянути стан контейнера:

```bash
docker compose ps
```

Перевірити таблиці та версію міграцій:

```bash
docker compose exec db psql -U postgres -d expenses -c "\dt"
docker compose exec db psql -U postgres -d expenses -c "SELECT * FROM alembic_version;"
```

Після застосування міграцій створюються таблиці `users`, `categories`, `records` та `alembic_version`. Поточна версія міграції — `0002`.

Дані зберігаються після перезапуску сервера та контейнера PostgreSQL завдяки Docker volume.

## Валідація

Для перевірки даних використовуються Pydantic-схеми.

Передбачено перевірку імен, ідентифікаторів, сум витрат та коректності JSON. При помилках сервер повертає відповідні HTTP-статуси `400`, `403` або `404`.

## Тестування

Для тестування використовується Bruno.

1. Запустити сервер.
2. Відкрити папку `bruno_collection` через Open Collection.
3. Вибрати середовище `Local`.
4. Виконати запити через Send або запустити всю колекцію через Runner.

Колекція містить 45 запитів у форматі YAML, зокрема перевірки персональних і глобальних категорій та обробки помилок.

Під час перевірки всі 45 тестів пройдено успішно.

## Основні файли

- `main.py` — API та обробка запитів
- `database.py` — підключення до PostgreSQL
- `models.py` — моделі бази даних
- `schemas.py` — валідація даних
- `alembic/` — міграції
- `docker-compose.yaml` — налаштування PostgreSQL
- `bruno_collection/` — колекція тестів Bruno
